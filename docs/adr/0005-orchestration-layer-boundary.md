# ADR-0005: 编排层的行数边界——继续拆会亏本

Date: 2026-11-12
Status: accepted（未完全解决）

## Context

把 `Diagnostics` 整段采集搬走后，`+Connect` 只从 **549 降到 499**。
剩下的行数是**连接流程本身**（connect / 地址解析 / 错误分派）。

要继续降，就得把 `connect()` 拆成独立类型，需要注入 **20+ 依赖**。

## Decision

**暂不继续拆，也不改阈值。** 记录在这里，等真有必要时再动。

真收益已经通过「抽出状态对象 + 纯逻辑下沉」拿到了——那两条是结构改善，
而继续按行数搬只是**行数在文件间转移，耦合不变**。

## Alternatives

| 备选 | 否决原因 |
| --- | --- |
| 继续按文件搬 | 行数转移，耦合不变（假收益） |
| 拆 `connect()` 成独立类型 | 要注入 20+ 依赖，改调用约定，风险高 |
| 把编排层阈值调到 600 | 改了阈值但没解决问题，只是让数字好看 |

## Consequences

**这是一条「不做」的决策，同样有价值**——否则每次有人看到 499 行都会重新提一遍「要不要拆」。

**代价**：编排层可能继续膨胀。**监控方式**是 `fact.json` 的行数趋势，
不是单次看某个文件。

Update (2026-11-16): 该问题在 `DSHPocket/Session` 整体上仍然存在（30 文件 6525 行）。
但结论不变：**按行数搬是假收益，按职责搬才是真的**（见 `docs/adr/0010`）。
