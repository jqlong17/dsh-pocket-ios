# ADR-0004: 文件行数阈值按层分级，extension 判据改为「拆了但职责没分开」

Date: 2026-11-12
Status: accepted

## Context

原规则是**一刀切 400 行**。实际后果：编排层被逼出一堆 197 行的碎片 extension，
**改一个功能要跳四个文件**——这比 600 行单文件更糟。

## Decision

| 层 | 上限 | 理由 |
| --- | --- | --- |
| `pure-logic` | 400 | 纯逻辑、可单测，必须短 |
| `app`（编排层） | 600 | 编排天然比策略长 |
| `ui-tests` | 600 | — |

**`extension-split-smell` 的判据改成**：
「≥3 个同前缀 extension **且其中仍有超阈值文件**」——即「拆了但职责没分开」。

**按职责拆 extension 是正常做法，文件数本身不是问题。**

## Alternatives

| 备选 | 否决原因 |
| --- | --- |
| 继续一刀切 400 | 逼出碎片 extension，改一个功能跳四个文件 |
| 按文件数限制 | 那是症状不是病因；真正该管的是「一个文件干几件事」 |

## Consequences

**收益**：不再为了行数而假拆分。

**代价**：编排层允许到 600 行，意味着**它仍可能继续膨胀**——
这正是 `docs/adr/0005` 记的未解决问题。

Update (2026-11-16): 实测当前最大文件 604 行（`ConnectionModel.swift`），在阈值内。
对比同类项目最大文件 7421 行，说明门禁是有效的。
